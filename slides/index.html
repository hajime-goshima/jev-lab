Jev とは5分

LLM は文章を書く。Jev は判定だけをする。

LLM に判定させると

  • 答えを文章で生成する
  • JSON で返させても、形が崩れることがある
  • パースと検証のコードが要る
  • 1件に数秒かかることも多い

Jev（System One モデル）

  • 型を決めた質問に、決まった型で答える
  • 答えと一緒に確率・確信度が返る
  • そのままコードで使える
  • 1件約0.2秒

「文章を読んで、決まった選択肢から選ぶ」ことに特化したモデル。人が数秒で直感的に答えられる判断を、プログラムから大量に速く行えます。

Jev とは ／ 特徴とコード5分

HTTP で JSON を1回送るだけ

  • 質問に名前を付けて、何問でも1回のリクエストにまとめる（前の3枚も、実際は3問を1回で送ったもの）
  • 入力は文字列でも JSON でもそのまま渡せる（画像・音声は未対応）
  • 応答は1件約0.2秒
  • 向かないこと：文章を書く、画像を見る、正規表現やコードで書ける厳密なルール
jev.rb（標準ライブラリだけ）
def ask(state, questions)
  req = Net::HTTP::Post.new(URL,
    "Authorization" => "Bearer #{@key}",
    "Content-Type"  => "application/json")
  req.body = { model: "jev-latest",
               state:, questions: }.to_json
  JSON.parse(@http.request(req).body)
end

# 使う側
a = jev.ask(text, QUESTIONS)["answers"]
a["sentiment"]["choice"]  # => "negative"

まとめ35分

判定を「処理の途中」に置けるのが Jev

3つに共通したコツ

  • そのまま渡す：文章も JSON も、前処理なしで state に
  • まとめて聞く：単純な質問に分けて、1回で最大6問
  • 確率で線を引く：確信度・しきい値で人に回す／止める
  • コードで書けるものはコードで：メール形式や root の判定は Jev に聞かない

限界

  • 問い合わせ文は AI が作成、CloudTrail の危険な操作は架空
  • しきい値は小さなサンプルで決めたもの
  • 苦手：遠回しな表現（74.3%）、文章の生成、画像
